# VK Feed Parser

Сбор постов VK по тегам — хештегом (`#тег`) или словом в тексте — за нужный период → Excel.
Сразу несколько аккаунтов, капча пережидается отлёжкой, прерванный сбор продолжается
с того же места.

Всё управление — панель в браузере (по умолчанию доступна только с этого компьютера):
**http://127.0.0.1:8787**
На сервере (Linux) панель открывают через SSH-туннель или ключ `--host` — см. §1.

---

## 1. Установка

Нужен Python **3.11 или 3.12** — https://www.python.org/downloads/
(на Windows при установке отметьте галочку **«Add python.exe to PATH»**).
Библиотеки и браузер Chromium панель поставит сама при первом запуске.

### macOS

1. Поставьте Python 3.11 или 3.12 с сайта выше (системный `python3` тоже подойдёт,
   но macOS часто не даёт ему ставить библиотеки).
2. Двойной клик по **`Запустить панель.command`**.
   macOS может ругаться на «неизвестного разработчика»: правый клик по файлу →
   «Открыть» → «Открыть».
   Из Терминала то же самое: `cd ~/Desktop/vk_feed_parser` и `python3 start_panel.py`.
3. Первый запуск скачает библиотеки и Chromium (~2–5 минут, нужен интернет),
   дальше панель поднимается за пару секунд.

### Windows

1. Поставьте Python 3.11 или 3.12 (галочка «Add python.exe to PATH»).
2. Двойной клик по **`Запустить панель.bat`** (или `start_panel.bat`).
   Если окно моргнуло и закрылось — из PowerShell в папке проекта:
   `.\start_panel.bat`

Панель должна открыться в браузере сама; если нет — адрес написан в окне запуска.

### Linux (в том числе сервер)

1. Поставьте Python 3.11 или 3.12 и системные пакеты:

   ```bash
   sudo apt update
   sudo apt install -y python3 python3-venv python3-pip
   ```

2. Запустите панель (первый запуск сам поставит библиотеки и Chromium):

   ```bash
   chmod +x start_panel.sh     # один раз: сделать файл исполняемым
   ./start_panel.sh            # то же, что python3 start_panel.py
   ```

3. На сервере без графики браузер не откроется — это нормально: адрес панели
   печатается в окне запуска. Смотреть её лучше через SSH-туннель (у панели нет
   пароля, в интернет её публиковать нельзя):

   ```bash
   ssh -L 8787:127.0.0.1:8787 user@сервер     # у себя в браузере: http://127.0.0.1:8787
   ```

   Если панель нужна прямо по сети: `./start_panel.sh --host 0.0.0.0 --no-browser`
   и закройте порт фаерволом (или поставьте перед панелью обратный прокси с паролем).

4. Вход в VK на сервере: окно входа требует экрана. Рабочие варианты:

   - токен в `data/accounts.txt` строкой `LOGIN:PASS:TOKEN` (токен `vk1.a.…`) — браузер не нужен;
   - войти на машине с экраном и скопировать на сервер `data/session_*.json`
     (и `data/vk_browser_profile*`, если нужен браузерный профиль);
   - виртуальный экран: `xvfb-run -a python3 src/vk_auth.py --login --account 1`.

   Под `sudo` Chromium стартует с `--no-sandbox`, а в контейнере добавляется
   `--disable-dev-shm-usage` — проект подставляет это сам.

5. Автозапуск после перезагрузки (systemd):

   ```ini
   # /etc/systemd/system/vk-feed-parser.service
   [Unit]
   Description=VK Feed Parser panel
   After=network-online.target

   [Service]
   User=vkparser
   WorkingDirectory=/opt/vk_feed_parser
   ExecStart=/opt/vk_feed_parser/.venv/bin/python /opt/vk_feed_parser/src/webui.py --port 8787 --no-browser
   Restart=on-failure
   RestartSec=10

   [Install]
   WantedBy=multi-user.target
   ```

   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now vk-feed-parser
   ```

   Панель слушает `127.0.0.1` — смотреть её с рабочего компьютера по-прежнему через
   SSH-туннель. Данные (`data/`) должны быть доступны пользователю из `User=`.

## 2. Порядок работы в панели

1. **Аккаунты** → «Добавить аккаунты…» → строка `телефон;пароль;2FA;прокси`
   или выдача `LOGIN:PASS:TOKEN` (токен `vk1.a.…` сразу станет сессией, без браузера).
   2FA и прокси можно не заполнять. Если сессии нет — **«Войти в VK»**: откроется
   Chromium, телефон и пароль скрипт подставит сам, а капчу («я не робот») решите
   в этом же окне; на экране «подтверждение входа» он сам перейдёт к вводу пароля.
2. «Проверить аккаунты» — статус должен стать «работает».
3. **Теги** → впишите теги (по строке, без `#` тоже можно) → «Добавить тег».
   Строки, начинающиеся с `# ` или `//`, — комментарии. Тут же переключатель
   **«Искать тег: с # (хештег) / без # (слово) / авто (по тегу)»** — он же настройка
   `tag_query`: *с #* ищет посты с хештегом (`маникюр` → `#маникюр`, как было
   всегда), *без #* — посты, где тег встречается в тексте **словом**, *авто* —
   решает по каждому тегу отдельно. У VK это **две разные выдачи**, и у нишевых
   тегов хештег почти пустой (люди пишут слово без решётки): по `#бровист` VK отдал
   7 постов за сутки, а словом — 171. Поэтому в *авто* тег один раз проверяется
   двумя запросами (хештег и слово за сутки), выбирается тот, где постов больше,
   и выбор запоминается в базе (`tags.query_mode`) — следующие «Старты» пробных
   запросов не делают. Режим `hash`/`word` действует на весь прогон (запрос по
   каждому тегу идёт одинаковый), `auto` — на каждый тег свой, и он сохраняется
   сразу в `data/settings.json`, так что следующий «Старт» его помнит; разово —
   флагом `--tag-query`.
   В таблице тегов у каждой строки две кнопки: **«В очередь»** возвращает тег к сбору
   (статус и курсор сбрасываются, собранные посты остаются в базе), а **«Обнулить
   счётчики»** обнуляет цифры «Постов/Страниц/Проходов» **и карточку «Постов в базе»**
   — она начинает считать с нуля (статус и курсор тега при этом не меняются). Отдельная
   кнопка нужна потому, что счётчики накопительные: «В очередь» их не сбрасывает, они
   только растут (`bump_tag`). Обнуление цифр не удаляет данные: посты и привязки
   остаются в базе, поэтому в подписи карточки видно «всего в базе N», а Excel и
   дедупликация работают по всей базе, как раньше (отметка отсчёта лежит в базе —
   `counter_mark`). То же из консоли: `python3 src/state_db.py --reset` (все теги в
   очередь) и `python3 src/state_db.py --reset-stats` (счётчики и карточка в нуль;
   `--only-unfinished` — только недоделанные теги).
4. **Прогон** → период (часы), «потоков» = сколько аккаунтов задействовать → «Старт».
   **Период — это ЧТО собирать, а не сколько работать:** прогон заканчивается, как
   только период охвачен, поэтому «за 6 часов» на уже собранных часах пролетает за
   минуту (в логе `период 6.0 ч из 6.0 ч (100%)`). Сколько работать, задаёт
   **«Работать, ч»**: поле подставляется по периоду («за 6 часов» → 6 ч, дольше суток
   по умолчанию не подставляется), отсчёт идёт от нажатия «Старт» — столько часов
   процесс непрерывно собирает посты: сначала проходится по периоду, дальше снова
   и снова проверяет свежий хвост и добирает только новые посты (как часто проверять —
   «Пауза, с»). «Работать, ч» = 0 — один проход: прогон закончится, как только период
   собран. «Стоп» прерывает.
   Лог идёт внизу страницы, Excel `data/exports/vk_feed_live.xlsx` обновляется по ходу.
   Долгий период — это сотни окон (например, «за 30 суток» × 20 тегов = 2400 окон):
   окна выдаются порциями, теги идут по кругу, и прогон не заканчивается, пока период
   не собран целиком — в логе видно `окон 480/480, период 720.0 ч из 720.0 ч (100%)`
   (в отчёте «период» — это запрошенный отрезок, а не сумма длин окон: окна хвоста
   нахлёстываются друг на друга).
   Уже собранные часы не переделываются, но свежий хвост периода (по умолчанию 6 часов,
   `refresh_tail_hours`) каждый «Старт» перепроверяется: лента меняется — приходят
   запоздавшие посты, обновляются лайки и комментарии. Перепроверка идёт строго внутри
   периода — запрос по окну обрезается по его границам, так что «за 6 часов» не залезет
   в прошлые сутки. Весь период заново — галочка «перепроверить весь период» (`--full`),
   совсем без повторов — «не перепроверять собранные часы» (`--no-refresh`).
   Панель можно не закрывать, окно браузера можно свернуть.
   **Видно, что делает прогон.** Галочка «показывать браузер (обход ленты + F5)» на
   странице «Прогон» (настройка `show_browser`, флаг `--show-browser`) открывает окна
   браузера. Их два вида:
   * **окно обхода** — сам поиск постов идёт HTTP-запросами (`newsfeed.search`), в
     браузере его не видно, поэтому окно открывает ту же выдачу, что берёт прогон: по
     тегу **с `#`** (хештег) или **словом без `#`** — как выбрано в `tag_query`
     (в режиме «авто» — так, как прогон решил по этому тегу) — и
     подписывает её: `обход ленты: #тег  15.11 01:00–15.11 02:00  окно #42  79990000001`
     (в режиме «без #» подпись та же, но без решётки: `обход ленты: тег (словом) …`) —
     видно, какое окно времени берётся прямо сейчас, а ниже — сколько постов уже в ленте
     (`(постов в ленте: 16)`): по этому числу видно, что лента живая и посты
     догружаются. Окно одно на прогон (живёт в своём потоке и
     в своём браузере, `_browser_lock` не занимает), окна времени его не ждут: показывается
     последнее. **F5 окно не жмёт вообще** — смену окна времени оно показывает
     **прокруткой выдачи**: страница приходит быстро, а посты в ней VK отдаёт только
     через несколько секунд — при перезагрузке на каждом окне (как было раньше) окно
     снова оказывалось пустым, посты не успевали прогрузиться, а каждая перезагрузка
     ещё и заметно тормозила окно. Выдача открывается заново только там, где листать
     больше нечего: другая выдача (сменился тег) или прокрутить не вышло (страница уехала
     на вход или закрылась). Окно открывается **мобильным экраном** (390×844, тач,
     телефонный user-agent — как лента в телефоне, и каждое новое окно берёт свой
     телефон): так VK отдаёт ту же выдачу лёгкой мобильной, и листает её окно
     **неровным шагом каждые 0.2–0.45 с** (`VIEW_SCROLL_MIN_SEC`–`VIEW_SCROLL_MAX_SEC`
     в `src/vk_auth.py`) — не только когда прогон взял новое окно времени, но и пока
     он его обходит: посты догружаются сами,
     а по числу постов в подписи видно, что лента живая. Закрывается окно само с
     концом прогона («Стоп», Ctrl+C, все окна собраны). Cookies сессии окно ставит так же,
     как их ставит сам браузер — на домен `.vk.ru`/`.vk.com`: VK спрашивает их и на своих
     поддоменах (`login.vk.ru`, `api.vk.ru`), а подстановка «на один vk.ru» оставляла окно
     анонимным — вместо ленты была «ошибка сети», а после F5 — страница входа. Если VK всё
     же просит вход, окно честно скажет об этом: подписью на самой странице
     (`VK просит вход: окно показывает страницу входа — обход идёт запросами`) и строкой в
     логе `окно на виду: VK просит вход вместо ленты …` (страницу входа окно не листает);
   * **окно эмулятора** — мелькает, когда эмулятор заходит в ленту, жмёт F5 и меняет
     cookies на свежий токен (обновление токена при проверке аккаунтов, F5 при пустой
     выдаче, фоновый обмен сессии): открывается на время такого обновления и закрывается
     через пару секунд после ленты. Лента в нём открывается тем же мобильным экраном, что
     и в окне обхода, а вход `--login` (там капчу и код вводит человек) остаётся широким.
   В логе при этом — `браузер работаю на виду (--show-browser): окно обхода покажет, какое
   окно времени берётся…`. По умолчанию галочка снята: браузер работает скрыто, как
   раньше, и прогон идёт молча. Показывать нужно уметь: на сервере без графической сессии
   окно показать нечем — в логе появится
   `показывать окно браузера не могу: графической сессии нет …`, и прогон пойдёт скрыто.
   Сбой окна обхода прогон не срывает: он идёт как обычно, а причина — строкой в логе
   (`окно на виду: показать обход не вышло …`). Окна браузера при обновлении сессии
   по-прежнему идут по одному (`--no-browser` выключает их совсем), так что показ их не
   размножает.
   **Сессия не протухает посреди прогона.** Токен VK живёт около суток, а сбор
   «за 30 суток» идёт часами: пока идёт работа, фон раз в `session_refresh_minutes`
   минут (по умолчанию 15) меняет токен аккаунтов на свежий и подставляет его уже
   работающим аккаунтам. Сначала это дешёвый обмен cookies; если VK его притормозил
   (`too much tries`) — фон открывает профиль браузера, обновляет ленту через **F5**
   и забирает cookies из живого браузера, а этот аккаунт дальше обновляется так же
   (для VK это обычный заход в ленту). В логе это видно как
   `сессию обновляю фоном каждые 2 мин` и `79000000000: сессия обновлена
   (cookies, клиентов 1)` или `(профиль браузера (F5), клиентов 1)` — живые аккаунты
   больше не выбывают до ручного входа.
   Выключить: `--no-session-refresh` или `"session_refresh_minutes": 0`.
   **Если прогон всё же встал из-за сессий.** Проверка перед стартом сама добывает
   свежий токен: на `access_token has expired` (VK отдаёт это и кодом 5, не только
   1117) аккаунт сначала открывает профиль браузера и обновляет ленту через F5,
   затем пробует обмен cookies — часто вход не нужен вовсе, и «Старт» проходит как
   обычно. А если сессии правда кончились, панель после
   `ПРЕДПОЛЁТ: готовых аккаунтов нет — прогон не запущен` сама открывает очередь входа
   (в логе `автовход: прогон не запустился (код 2, готовых аккаунтов нет) — вход в VK
   для N аккаунтов…`): окна идут по одному, как у кнопки «Войти во все, кому нужен
   вход», пароль и капчу вводит человек. Не хотите окон — выключите:
   `"auto_login_on_fail": false` в `data/settings.json`
   (`python3 src/settings.py --auto-login-on-fail off`), тогда входить только кнопкой.
   **Скорость.** Один аккаунт делает не чаще одного запроса в
   `min_call_gap_sec`–`max_call_gap_sec` секунд (в `data/settings.json`;
   по умолчанию 3.5–4.5 с — VK режет всплески). Со своим прокси на каждый аккаунт
   можно ставить 1.5–2.5 с — это самый заметный ускоритель прогона.
   VK отдаёт за один запрос ~30–60 постов независимо от «постов на страницу»,
   поэтому быстрее всего добавлять аккаунты с личными прокси, а не «потоки».
   В логе видно, что применилось: `по 200 постов/запрос, лимит 1.5–2.5 с/запрос`.
   Заодно вдвое сокращены все таймауты: запрос к VK 15 с, открытие
   страницы входа 22.5 с, ожидание входа 450 с, отлёжка аккаунта от 30 с
   (пауза при пустой выдаче не нужна вовсе: если VK молча отдал пустую
   страницу, запрос меняем сразу, см. ниже).
   **Повторы.** Один и тот же пост у разных сообществ — обычное дело в VK.
   `dedupe_posts` в `data/settings.json` не даёт писать повторы по тексту:
   `tag` — если такой текст уже собран по этому тегу, `global` — если вообще в
   базе, `off` — писать всё (как раньше). Мусор из одних хештегов
   («#ногти #маникюр») убирает `min_text_chars` (например, 15 знаков
   осмысленного текста). Сколько постов не записали, видно в итоге прогона:
   `не записано: повторов по тексту 1737, мусорных постов 0`.
5. «Стоп» — то же, что Ctrl+C: прогресс остаётся в базе, следующий «Старт» продолжит
   с того же места. Прерванные окна доделываются автоматически.

## 3. Несколько аккаунтов (мультиаккаунт)

- `data/accounts.txt` — по строке на аккаунт: `телефон;пароль;2FA_СЕКРЕТ;прокси`.
  Порядок строк = номер аккаунта. Строки с `#` или `//` в начале — комментарии.
- Вход у каждого аккаунта свой: сессии лежат в `data/session.json` и
  `data/session_<телефон>.json`, профиль браузера — `data/vk_browser_profile_<номер>`
  (уже вошедший аккаунт использует свою прежнюю папку профиля). Входы друг другу не мешают.
  Кнопка «Войти в VK» в строке аккаунта — это
  `python3 src/vk_auth.py --login --account N`.
- Кнопка «Войти во все, кому нужен вход» (там же, страница «Аккаунты») делает то же
  самое для всех, кому вход нужен: у кого файла сессии нет **и** у кого сессия мертва
  (`access_token has expired` — такая строка помечена «войти заново»). Окна открываются
  по очереди — следующее после того, как вы закончили с предыдущим. Пароль и капчу
  в каждом окне по-прежнему вводит человек. Прервать очередь: та же кнопка или «Стоп».
  Ту же очередь панель открывает сама, если прогон не запустился из-за сессий: в логе
  `автовход: прогон не запустился (код 2, готовых аккаунтов нет) — …` (выключить:
  `"auto_login_on_fail": false`).
- Потоки: больше, чем живых аккаунтов, движок не запустит — в логе видно
  `аккаунтов 3 (готовы 1, отлёжка 0, мертвы 2), воркеров 1`.
  Воркеры не закреплены за аккаунтом: освободился — берут следующий живой.
- Капча/лимит → аккаунт уходит в «отлёжка» (от минуты до часа) и возвращается сам.
  «Мёртв» = нужен повторный вход («Войти в VK»). До этого дело обычно не доходит:
  пока идёт прогон, токен аккаунтов меняется на свежий сам
  (`session_refresh_minutes`, по умолчанию 15 мин).
- Пустая выдача от VK (в логе `ВК молча отдаёт пустую выдачу — беру то же окно другим
  запросом`) — это тихое ограничение, а не «постов нет»: VK ответил без ошибки, но
  отдал пустую страницу, хотя в базе посты за эти часы уже есть (а если их нет —
  канарейка, час у самого свежего поста, подтвердила, что сессия жива и отвечает).
  Пауза тут
  не помогает — ответ VK на том же запросе не меняется, поэтому движок меняет сам
  запрос, без ожидания:
  1. **F5 в профиле браузера** — сессия освежается, то же окно берётся заново (в логе
     `F5 в профиле — сессия освежена, клиент работает новым токеном` и
     `беру окно заново — сессия освежена через F5`). Не больше двух раз **на аккаунт за
     прогон** (это открытие браузера — самое дорогое действие), и на половинках окна
     он не повторяется. `--no-browser` этот шаг выключает, а `--show-browser` (галочка
     «показывать браузер (обход ленты + F5)», настройка `show_browser`) его, наоборот,
     показывает: видно, как эмулятор заходит в ленту и жмёт F5 (плюс окно обхода ленты —
     так же, как при обычных окнах, см. описание показа выше).
  2. **Другой прокси** — `F5 не помог — меняю прокси 45.88.208.121:3323 →
     37.77.147.17:3323, беру окно заново`: сессия свежая, а выдача та же — значит
     помечен не токен, а адрес. Аккаунт получает первый свободный прокси из запаса
     (`data/proxy_stock.txt`, пополняется на странице «Прокси»), прежний адрес
     возвращается в запас (в конец — достанется кому-то последним), в `accounts.txt`
     и в базе пишется новый, и окно берётся заново уже с нового адреса. **Одна смена
     на аккаунт за прогон**, и она работает даже в общем «тихом» режиме (когда VK
     режет выдачу всем аккаунтам, смена адреса — самая осмысленная проба). Запаса нет
     — шаг пропускается с одной строкой в логе (`прокси сменить нечем — в запасе нет
     свободных прокси; лестница дальше как есть (добавить: панель → «Прокси»)`).
     Выключить: `--no-proxy-swap`. Сожжённый адрес считается свободным — если он
     больше не нужен, удалите его строку из `data/proxy_stock.txt`.
  3. **Другой `count`** — та же страница запрашивается меньшими порциями
     (`count 200 → 50, без паузы`): для VK это другой запрос, а меньшая страница
     листается дальше, посты не теряются.
  4. **Окно пополам** — `делю окно пополам, половинки беру отдельными запросами`:
     половинки уже меньше режутся тихим нулём. Не больше одного окна **на аккаунт за
     прогон**: иначе из-за одного застрявшего окна очередь растёт с каждым запуском.
  5. **Другому аккаунту** — `отдаю другому аккаунту`: окно уходит в конец очереди, его
     берёт живой аккаунт, а текущий не занимается паузами.

  Лестница проходит **один раз на окно и один раз на аккаунт за прогон**: счётчики живут
  на аккаунте весь прогон, поэтому на половинках окна и после отлёжки она не повторяется
  (раньше после каждой отлёжки аккаунт заново жал F5, менял `count` и дробил окна —
  на 13 молча пустых окон уходили сотня запросов, десяток открытий браузера и лишние
  окна из дробления). Если и живой аккаунт видит ту же пустоту, окно остаётся в базе
  `pending` и его добьёт следующий «Старт» (`молча пустое — оставляю следующему
  «Старту»`) — в панели об этом появляется предупреждение. Половинки одного окна
  считаются одним окном, поэтому аккаунт уходит в «отлёжка» только после пустоты на трёх
  разных окнах подряд, а дальше работает «тихо»: в логе `дальше лестницу не повторяю —
  окна беру одним запросом`, в панели `лестницу (F5 и дробление) не повторяю…`. В тихом
  режиме каждое пустое окно стоит ровно один запрос к VK (плюс, один раз на аккаунт,
  проба смены адреса), окна не дробятся и остаются в базе для следующего «Старта» —
  серия из 13 пустых окон стоит ~13 запросов и ни одного
  открытия браузера. Тихий режим снимается, как только пришёл хоть один пост.
  **Если VK молчит сразу у всех аккаунтов** (разных пустых окон подряд по всему прогону
  стало 10), включается общий «тихий» режим: в логе одна строка `ВК молча отдаёт пустую
  выдачу на N разных окнах подряд по всем аккаунтам — лестницу выключаю, окна беру одним
  запросом`, лестницы (F5, смена прокси, другой `count`, дробление, передача) и записей
  в панель по каждому окну больше нет — окно стоит ровно один запрос. После 40 таких окон раунд
  прерывается (`ВК молча режет выдачу всем аккаунтам — раунд прерван, недобитых окон N
  добьёт следующий «Старт»`) — вместо того чтобы выжечь очередь сотнями пустых запросов и
  строк лога. В режиме «Работать, ч» прогон на этом не кончается: он ждёт 5 минут и
  пробует снова (`пауза …, потом проверю снова`) — ограничение VK обычно отпускает само, а
  недобитые окна всё это время лежат `pending`. Счётчик обнуляется первым же постом;
  вмешиваться не нужно.
  **Старый участок периода** прогон **не пропускает**: «первый пост в базе» — не
  предел выдачи VK. Раньше окно, целиком лежащее раньше самого раннего поста тега,
  закрывалось сразу и без запроса (`out_of_period`): считалось, что глубже VK постов
  не отдаёт. На живой сессии это оказалось не так — у «бровиста» первый пост был
  12.10, а VK спокойно отдаёт 05.10 (45 постов на окно в 6 ч словом, 9 — хештегом).
  Поэтому 125 окон участка 18.09–12.10 «закрылись» без единого запроса, и эти часы
  навсегда выпали из сбора. Теперь старые окна спрашиваются как все.
  Если окно пустое, а постов за него в базе ещё нет, повтор ставится **в конец
  очереди**, а не перед собой: мгновенный повтор получает тот же пустой ответ, а
  через круг очереди (минуты) тихое ограничение обычно уже отпускает — так часы не
  закрываются как «собрано» из-за минутной тишины VK.
  Браузер не открывать: `--no-browser`.
- Лимиты выдачи VK учтены в движке, а не «на глазок»: `count` — не больше 200
  записей за запрос (значение из настроек и `--page-count` обрезается в
  `src/vk_client.py`), страницы листаются `next_from` → `start_from` (не `offset`),
  а окно, дошедшее до первых **1000** результатов, помечается на дробление: глубже
  `newsfeed.search` не отдаёт, и остаток собирают половинки окна, а не
  повторяющиеся страницы. Параметров «сортировка» и «случайный параметр от кеша»
  у метода нет — в запросе только `q`, `count`, `start_time`, `end_time`,
  `start_from`, `extended` и `fields`, поэтому подмешивать их бессмысленно: VK их
  игнорирует, а выдача от этого не меняется.
- Прогон ходит в VK **телефоном**: User-Agent — Android (Chrome) или iPhone (Safari),
  и **на каждый запрос страницы он другой** (`src/user_agents.py`). Вместе с UA меняется
  импресонация curl_cffi (TLS, HTTP/2, порядок заголовков) и client hints — у Android они
  «?1»/Android с версией Chrome из UA, у iPhone их нет вовсе (Safari их не шлёт): запрос не
  выглядит настольным Chrome с поддельным UA. Стартовый UA сессии и обмен cookies на токен
  — тоже телефонные. Настольный UA остался только у окна входа `--login`: это широкая форма,
  капчу и код в ней вводит человек.
- Прокси берётся из строки аккаунта, а если там пусто — из `proxies.txt`
  (строка с тем же номером, что и аккаунт). Слово `direct` (или `none`, `-`)
  вместо адреса значит работу без прокси. Проверка — кнопка «Проверить прокси».
- Прогон сам правит адрес аккаунта в одном случае: когда VK молча отдаёт пустую
  выдачу даже после F5 — тогда аккаунту ставится свободный прокси из запаса
  (`data/proxy_stock.txt`), а прежний адрес возвращается в запас (см. лестницу выше).
  Смена одна на аккаунт за прогон, выключается `--no-proxy-swap`.
- Колонка «Прокси» в таблице аккаунтов показывает то, что реально пойдёт в работу
  (из `accounts.txt` / `proxies.txt`); пусто («—») — это `direct`, вход напрямую.

## 4. Если что-то не так

| Симптом | Что делать |
|---|---|
| `python: command not found` (macOS) | команда называется `python3`; проще запускать `Запустить панель.command` |
| «Chromium не установился» | проверьте интернет и запустите панель снова (или `python3 -m playwright install chromium`) |
| Аккаунт «мёртв — токен не обновлён (нужен curl_cffi)» | запуск шёл Python без библиотек: запускайте через `Запустить панель.command` / `python3 start_panel.py` — он сам выберет подходящий Python |
| Аккаунт «мёртв — нет файла сессии» | нажмите «Войти в VK» в строке аккаунта или «Войти во все, кому нужен вход» — входы пойдут по очереди |
| Аккаунт «мёртв — access_token has expired» (протух токен, файл сессии есть) | обычно вход не нужен: проверка перед «Старт» сама меняет токен (профиль браузера с F5 → cookies) — VK отдаёт «has expired» и кодом 5, и кодом 1117. Если не помогло, панель после `ПРЕДПОЛЁТ: готовых аккаунтов нет` сама открывает очередь входа (в логе `автовход: …`). Вручную: «Войти в VK» в строке аккаунта или «Войти во все, кому нужен вход» — обе кнопки берут и протухшие сессии (пометка «войти заново») |
| Окно входа пустое (`about:blank`) или в логе `Timeout … domcontentloaded` | виноват обычно прокси аккаунта (нет соединения или туннель оборвался): вход сам повторит попытку, а если прокси «мёртв» — прямо скажет об этом. Смените прокси в `data/accounts.txt` и войдите снова |
| Вошли, а VK показывает QR-код | отсканируйте его приложением VK или просто подождите ~25 секунд — скрипт сам перейдёт к вводу телефона и пароля |
| VK просит код из SMS/MAX | код можно не ждать: скрипт сам нажмёт «Войти при помощи пароля». Если код уже пришёл — введите его в окне |
| Вход «висит» и панель не даёт нажать «Старт» | закройте панель и откройте заново (незавершённый вход она считает активным процессом) |
| Порт 8787 занят | панель сама возьмёт следующий порт и напишет адрес в окне |
| «нет tkinter» | это про старое окно (`Запустить окно.bat`); панель в браузере работает без него |
| Библиотеки не ставятся на Python 3.13/3.14 | поставьте 3.11 или 3.12: колёса `curl_cffi` есть не под все версии |
| Прогон застрял на старых окнах | «Стоп» и «Старт» заново: остатки прошлого прогона, чьи часы уже собраны другими окнами, снимаются сами (в логе `окна прошлого запуска уже собраны другими окнами: брошено …`). Бросить все недоделанные окна: `python3 src/run_tags.py --no-resume` |
| Очень медленно, мало постов за прогон | смотрите лимит запросов: в логе `лимит 1.5–2.5 с/запрос` — это пауза на каждый запрос одного аккаунта. С личным прокси на аккаунт можно опускать до 1.5–2.5 с (`python3 src/settings.py --call-gap 1.5 --call-gap-max 2.5`) и добавить аккаунты с прокси: VK отдаёт всего ~30–60 постов за запрос, поэтому «потоки» на одном аккаунте ничего не ускоряют. Не поднимайте лимит вслепую: VK отвечает кодом 6/9, и прогон становится только медленнее |
| В логе `токены части аккаунтов просрочены` или `access_token has expired` | сессия протухла (VK меняет токены): «Войти в VK» в строке аккаунта или `python3 src/vk_auth.py --login`. Окна, которые оборвались с такой ошибкой, «Старт» теперь возвращает в очередь сам (в логе `возвращено в очередь брошенных окон: 179`). Проверка перед стартом такие токены меняет сама (профиль браузера: лента + F5, затем cookies) — VK отдаёт «has expired» и кодом 5, и кодом 1117, — поэтому обычно «Старт» проходит без входа; чтобы до этого не доходило посреди прогона, токены аккаунтов меняются на свежие автоматически (`session_refresh_minutes`) |
| В логе `сессию обновляю фоном каждые 15 мин`, `79000000000: сессия обновлена (cookies, клиентов 1)` | так и надо: токен VK живёт около суток, а сбор идёт часами — фон заранее меняет токены аккаунтов на свежие, поэтому живые аккаунты не выбывают посреди работы. Как часто: `session_refresh_minutes` в `data/settings.json` (`python3 src/settings.py --session-refresh-minutes 15`), выключить: `--no-session-refresh` или `0` |
| В логе `сессию обновить не вышло (cookies: … too much tries)` | VK ограничил частоту HTTP-обмена cookies. Фон сразу идёт в профиль браузера: открывает ленту, жмёт F5 и меняет cookies живого браузера на свежий токен (в логе `сессия обновлена (профиль браузера (F5), клиентов 1)`) — для VK это обычный заход в ленту, а не обмен токена. Если и это не прошло, старый токен остаётся рабочим, следующая попытка через 5 минут. Приходит постоянно — поставьте `session_refresh_minutes` 15–30: токен живёт сутки, чаще обменивать его не нужно |
| В логе `сессию обновить не вышло (cookies: в сессии нет remixsid…)` | сессия аккаунта правда умерла: cookies не приняты, фон открывает профиль браузера и жмёт F5 на ленте, а если и он не помог — «Войти в VK» в строке аккаунта |
| В логе `ВК молча отдаёт пустую выдачу — беру то же окно другим запросом` | так и надо: VK принял запрос, но отдал пустую страницу — тихое ограничение (посты за эти часы в базе уже есть, а если их нет — канарейка, час у самого свежего поста, показала, что сессия жива). Пауз нет: движок сразу меняет запрос — F5, затем `count 200 → 50, без паузы`, затем делит окно пополам, затем отдаёт окно другому аккаунту. Лестница идёт один раз на окно и один раз на аккаунт за прогон: F5 — не больше двух на аккаунт (это открытие браузера), смена прокси — одна, дробление — не больше одного окна, на половинках окна шаги не повторяются. Смотрите, помог ли следующий шаг: `делю окно пополам` / `молча пустое даже после смены запроса — отдаю другому аккаунту`. Вмешиваться не нужно; браузер не открывать — `--no-browser` |
| В логе `окно … молча пустое — оставляю следующему «Старту»`, хотя часы старые | это не пропуск: старый участок периода прогон спрашивает у VK как все. «Первый пост в базе» — не предел выдачи VK: у «бровиста» первый пост 12.10, а VK отдаёт 05.10 (45 постов на окно в 6 ч). Пустое окно, по которому в базе ещё нет постов, повторяется **в конце очереди** (через круг тихое ограничение обычно отпускает), а не закрывается как «собрано» с первого пустого ответа |
| В консоли окна на виду `stats.vk-portal.net … net::ERR_FAILED`, `akashi.vk-portal.net … blocked by CORS`, `Service Worker was not registered`, `Not found blocking … asset from window_proxy.js` / `performance_observers.js` | это не «VK увидел софт»: окно на виду **само** не грузит рекламу и чужую статистику (`VIEW_NOISE_HOSTS`), поэтому заблокированные счётчики и пишут `ERR_FAILED`/CORS, а service worker и manifest — обычные сообщения мобильной страницы VK. `Not found blocking` печатает собственный загрузчик статики VK (`window.vk.static` в `first_wave_vendors.js`): он строит адрес ассета как `window.vk.static.domain + путь` и ищет тег по префиксу (`link[href^=…]` / `script[src^=…]`). Если страница пришла с одного CDN-хоста (`st1-29.vk.ru`, `st7-14.vk.ru`), а в конфиге страницы стоит другой (`st.vk.ru`), тег «не находится» — отсюда **warn**; сами файлы на всех этих хостах отдаются (200, байт в байт одинаковые), ленте они не нужны, и обход идёт дальше. От User-Agent эти строки не зависят: живой Chromium с Android, iPhone и настольным UA даёт ту же пару строк — меняется только зеркало, которое выбрал сервер. Поэтому смена UA или прокси тут ничего не лечит (а прокси у окна и так тот же, что у аккаунта). Окно на виду глушит ровно эту строку (`VIEW_CONSOLE_MUTE_JS`): в консоли окна остаются настоящие ошибки страницы. Обход идёт HTTP-запросами, окно лишь показывает ту же выдачу. Признаки ограничения VK другие и видны **в логе прогона**, а не в консоли окна: капча (ошибка 14), `Flood control`/ошибка 9, `too much tries` на обмене cookies на токен, `access_token has expired` |
| В логе `F5 не помог — меняю прокси 45.88.208.121:3323 → 37.77.147.17:3323, беру окно заново` | так и надо: сессию освежили (F5), а выдача та же — значит помечен не токен, а адрес аккаунта. Движок берёт аккаунту первый свободный прокси из запаса (`data/proxy_stock.txt`), прежний адрес возвращает в запас (в конец — достанется кому-то последним), в `accounts.txt` и в базе пишет новый и берёт окно заново. Смена одна на аккаунт за прогон и работает даже в общем «тихом» режиме. В панели об этом — событие «меняю прокси»: там же видно новый адрес в колонке «Прокси». Выключить смену: `--no-proxy-swap` |
| В логе `прокси сменить нечем — в запасе нет свободных прокси` | запас пуст: свободных адресов нет (или все уже стоят у аккаунтов — один адрес на аккаунт). Добавьте прокси на странице «Прокси» («Добавить» → «Привязать к аккаунтам»), файл запаса — `data/proxy_stock.txt`. Строка пишется **один раз на аккаунт**, а не по каждому окну: прогон просто идёт по лестнице дальше |
| «Постов в базе» показывает 0, хотя постов в базе тысячи | так и надо после «Обнулить счётчики»: отсчёт карточки сдвигается (отметка `counter_mark` в базе), подпись меняется на «Постов с обнуления», а рядом видно «всего в базе N». Сами посты не удаляются — Excel и дедупликация по-прежнему видят всю базу. Вернуть карточке всю базу: снять отметку — `sqlite3 data/parser.sqlite3 "DELETE FROM counter_mark"` (обычно этого не нужно: «всего в базе N» есть в подписи карточки и в `python3 src/state_db.py --stats`) |
| Хочется, чтобы VK видел телефон, а не ПК | так и есть: каждый запрос страницы (`newsfeed.search`) уходит мобильным UA — Android или iPhone — и на каждой странице он **другой** (`src/user_agents.py`); вместе с UA меняются импресонация curl_cffi (TLS/HTTP2) и client hints. Стартовый UA сессии и обмен cookies на токен — тоже телефонные. Настольный UA остался только у окна входа `--login`: это широкая форма для человека (капча, код, QR) |
| Во время прогона сами открываются окна браузера | так и надо, если включена галочка «показывать браузер (обход ленты + F5)» (`show_browser` / `--show-browser`). Окно обхода открывает ту же выдачу по тегу, что берёт прогон (с `#` или словом — как в `tag_query`), и подписана она так: `обход ленты: #тег  15.11 01:00–15.11 02:00  окно #42  79990000001` — видно, какое окно времени берётся; окно одно на прогон и закрывается с его концом. Окно эмулятора мелькает, когда сессия обновляется через ленту (F5): держится пару секунд после ленты и закрывается само. В логе об этом — `браузер работаю на виду (--show-browser): окно обхода покажет, какое окно времени берётся…`. Окна не нужны — снимите галочку или уберите `--show-browser`; совсем без браузера — `--no-browser` |
| Галочка «показывать браузер» включена, а окна не видно | показывать нечем: нужна графическая сессия. В логе это видно строкой `показывать окно браузера не могу: графической сессии нет (…) — эмулятор работает скрыто (на сервере так и надо)`, и прогон идёт скрыто, как обычно. Проверьте, что галочка действительно включена (она хранится как `show_browser` в `data/settings.json`: `python3 src/settings.py --show-browser on`), и что прогон запущен без `--no-browser` — он выключает браузер совсем, и показывать становится нечего. Если окно уже было, а потом исчезло — смотрите лог: сбой окна обхода прогон не срывает, о нём пишется `окно на виду: показать обход не вышло (…) — прогон продолжается как обычно`, после трёх сбоев показ выключается сам |
| В панели предупреждение `ВК молча отдаёт пустую выдачу, окно добьёт следующий «Старт»` и в логе `молча пустое — оставляю следующему «Старту»` | все шаги (F5, смена прокси, другой `count`, половинки, другой аккаунт) не помогли: окно осталось в базе `pending` целиком и его добьёт следующий «Старт» — потерь нет. Если пустых окон подряд три и больше, аккаунт переходит в «тихий» режим — в логе `дальше лестницу не повторяю — окна беру одним запросом`, в панели `лестницу (F5 и дробление) не повторяю…`: каждое пустое окно стоит ровно один запрос к VK, окна не дробятся и ждут в базе следующий «Старт» (раньше аккаунт после каждой отлёжки начинал лестницу заново и молотил те же пустые выдачи). Если таких окон много, тихий ноль держится долго: подождите (такое ограничение отпускает само) или прогоните тег ещё раз, добавив аккаунт с прокси |
| В логе `ВК молча отдаёт пустую выдачу на N разных окнах подряд по всем аккаунтам — лестницу выключаю, окна беру одним запросом` | так и надо: тихое ограничение не у одного аккаунта, а сразу у всех — лестница (F5, другой `count`, дробление, передача другому аккаунту) тут ничего не меняет, только множит запросы и строки в логе. Одну пробу смены прокси движок всё же оставляет — по разу на аккаунт: если VK режет выдачу по адресам, помогает только она (`F5 не помог — меняю прокси …`). Общий счётчик разных пустых окон по всему прогону дошёл до 10 — движок выключает лестницу и предупреждения по каждому окну, каждое окно стоит ровно один запрос. Счётчик обнуляется первым же постом — вмешиваться не нужно |
| В логе `ВК молча режет выдачу всем аккаунтам — раунд прерван, недобитых окон N добьёт следующий «Старт»` | так и надо: пустых окон подряд стало 40 — движок не выжигает очередь (раньше на 350 недобитых окон уходили сотни запросов и строк лога, а новых постов было 0). Недобитые окна остались в базе `pending` и их добьёт следующий «Старт». В режиме «Работать, ч» вместо простоя в логе `ВК молча режет выдачу всем аккаунтам — пауза 5 мин, потом проверю снова`: прогон сам повторит попытку, когда ограничение VK отпустит (обычно 30–60 минут) |
| В логе `в профиле нет remixsid — сессия кончилась, нужен вход --login` или `профиль+F5 не помог (…) — пробую полный вход в профиль` | профиль браузера больше не помнит аккаунт, поэтому токен без человека не добыть: «Войти в VK» в строке аккаунта (вход откроет то же окно, и после него F5-путь снова работает) |
| В логе `ПРЕДПОЛЁТ: готовых аккаунтов нет — прогон не запущен` и `автовход: прогон не запустился (код 2, готовых аккаунтов нет) — …` | так и надо: ни у одного аккаунта нет рабочей сессии, поэтому панель сама открыла очередь входа. Введите пароль/капчу в окнах — или просто подождите: если профиль браузера ещё помнит аккаунт, вход пройдёт сам. После входа нажмите «Старт». Окна не нужны — `"auto_login_on_fail": false` в `data/settings.json`, тогда вход только кнопкой «Войти во все, кому нужен вход» |
| В Excel много одинаковых постов | это повторы от разных сообществ: `"dedupe_posts": "global"` в `data/settings.json` — новые повторы писаться не будут; уже собранные почистит `python3 src/state_db.py --drop-text-dupes --apply --keep likes` (примерка без `--apply`) |
| «Постов в базе» меньше, чем «ссылок» | так и должно быть: «постов» — уникальные посты (`owner_id_post_id`), «ссылок» — привязки «пост × тег». Пост, найденный по двум хештегам, лежит один раз, а привязок у него две. В Excel теперь одна строка на пост, теги перечисляются в колонке «Теги» |
| «Постов»/«Страниц» у тега не обнуляются после «В очередь» | так и надо: «В очередь» сбрасывает состояние и курсор тега, а цифры — история за всё время, они только растут. Обнулить: кнопка «Обнулить счётчики» у тега (есть и в панели, и в окне) или `python3 src/state_db.py --reset-stats` — статус и курсор при этом не трогаются |
| Постов мало, хотя по тегу их должно быть много (или наоборот: полезло «не то») | проверьте, **чем ищется тег**: переключатель «Искать тег: с # (хештег) / без # (слово) / авто (по тегу)» на странице «Теги» (настройка `tag_query` в `data/settings.json`, `python3 src/settings.py --tag-query word`, разово — флаг `--tag-query`). У VK хештег и слово — это **две разные выдачи**: «без #» находит посты, где тег просто упомянут словом в тексте, «с #» — только посты с хештегом. У нишевых тегов хештег почти пустой: по `#бровист` VK отдал 7 постов за сутки, а словом — 171, и прогон по хештегу выглядел как «0 постов». Проще всего поставить **«авто»**: тег один раз проверяется обоими запросами, выбирается тот, где выдача больше, и выбор запоминается в базе (`tags.query_mode`). В логе видно решение: `#бровист: за 24 ч хештегом 7, словом 171 — ищу словом`. Если режим задан явно (`hash`/`word`), режим виден до первого запроса: `тег в запросе: без # (слово) — ищу слово в тексте постов…`; окно обхода ленты показывает ту же выдачу, что собирает прогон |
| В логе `окно брошено после 3 попыток (api_1117)` | раньше такие окна пропадали навсегда; теперь окна внутри периода «Старт» возвращает в очередь. Если ошибка повторяется — проверьте вход: 1117 это истёкший токен |
| В логе `брошено … окон прошлого запуска вне периода` | так и надо: в базе лежали окна прерванного прогона **вне** запрошенного периода (например, остатки сбора за прошлые недели при запуске «за 6 часов») — они снимаются с очереди. Окна **внутри** периода по-прежнему добираются: «Старт» продолжает с того же места. Бросить всё разом: `--no-resume` |
| Прогон «за 30 суток» идёт долго | так и должно быть: 30 суток × десятки тегов — сотни окон, аккаунты идут по кругу, а прогон не останавливается, пока период не собран целиком (в логе `окон 480/480 … (100%)`). Капча или лимит — аккаунт уходит в отлёжку и возвращается сам |
| Поставил «за 6 часов», а прогон закончился за минуту | так и должно быть: период — это ЧТО собирать, а не сколько работать. За эти 6 часов всё уже собрано (и хвост перепроверен), поэтому работа кончилась сразу — в логе `период 6.0 ч из 6.0 ч (100%)`. Работать долго и подбирать новые посты — поле **«Работать, ч»** (флаг `--run-hours`; в логе это `работаю N ч`), оно подставляется по периоду («за 6 часов» → 6 ч): в логе появится `работаю 6 ч`, и процесс будет непрерывно проверять свежий хвост и добирать новые посты. Если поле оставить 0, прогон честно скажет об этом сам: `период уже был собран целиком до запуска — работа сводилась к перепроверке свежего хвоста … «Работать, ч» 6`. Без панели: `--run-hours 6` |
| В логе `время вышло — завершаю` | прогон отработал своё время, а не число проходов: так и задумано. Код выхода 0 (не ошибка), недобитые окна остаются в базе — кнопка «Старт» снова возьмётся за них. Число проходов не ограничивает «Работать, ч» |
| В логе `новых постов нет — проверю снова` | сбор идёт, но подбирать пока нечего: свежий хвост периода (`refresh_tail_hours`) собран, а новых постов ВК ещё не отдал. Так и должно быть: круг, который не принёс ни одного нового поста, ждёт «Пауза, с» и проверяет снова — это ровно один запрос к VK на круг (и один разбор окна), а не повторы того же пустого окна каждые пару секунд. Если хвост выключен (`--no-refresh` или `refresh_tail_hours: 0`), ждать нечего — лучше поставить «Работать, ч» = 0 |
| В логе `собирать нечего: период уже пройден целиком` | за этот период всё уже собрано, включая свежий хвост: перепроверять нечего. Обновить свежие часы: `--refresh-hours 12`, весь период заново: «перепроверить весь период» (`--full`) |
| В логе `хвост … ч перепроверяю — лента меняется` | так и надо: свежие часы периода перепроверяются, потому что лента меняется — приходят запоздавшие посты, обновляются лайки (счётчики окна берутся заново, окно не дробим и не создаём новых строк, а запрос обрезаем по границам периода). Выключить: `--no-refresh` или `refresh_tail_hours: 0` в `data/settings.json` |
| В логе `период 6.0 ч из 6.0 ч (100%)`, хотя окон 11 | так и надо: часы считаются по охвату периода (собранное в базе + розданное в этом прогоне), а окна хвоста нахлёстываются друг на друга. Сколько окон ещё в работе — смотрите на `окон 0/11` в той же строке |
| В логе `уже собрано … ч из периода — пропускаю` | это про часы **старше** свежего хвоста (`refresh_tail_hours`, по умолчанию 6 ч) — их в базе уже прошли, второй раз не качаем. Пройти весь период заново: «перепроверить весь период» (`--full`) |
| В логе `постов 24, новых 0` | так и надо: эти часы уже собраны (перепроверка хвоста, половинки после дробления или остатки прошлого запуска) — лента отдаёт по ним те же посты, что лежат в базе, поэтому ни один не попал в счётчик «новых». Если «новых 0» идёт сплошняком, смотрите на общий прогресс в строке `в очереди … окон — … период 399.2 ч из 720.0 ч (55%)`: несобранные часы ещё ждут очереди |
| В теге собралось меньше постов, чем видно в VK | у `newsfeed.search` жёсткий лимит: 200 записей за запрос и первые 1000 результатов на запрос — глубже VK не отдаёт. Парсер не обходит это `offset`-ом: окно, упёршееся в 1000, делится по времени, и остаток добирают половинки. Если постов всё равно мало — проверьте режим тега (хештег и слово — разные выдачи, см. `tag_query`) и нет ли в логе `ВК молча отдаёт пустую выдачу` |
| В логе `окна прошлого запуска уже собраны другими окнами: брошено …` | так и надо: остатки прерванного прогона, все часы которых уже собраны другими окнами, снимаются с очереди — иначе «Старт» часами перечитывал бы их (`постов N, новых 0`), а непройденные часы ждали. Окна, где остались несобранные часы, по-прежнему добираются («Старт» продолжает с того же места). Перепроверить всё: `--full` |
| Панель нужна по сети (сервер), а её видно только с самого сервера | у панели нет пароля: безопаснее SSH-туннель `ssh -L 8787:127.0.0.1:8787 user@сервер`; если нужен прямой доступ — `--host 0.0.0.0` и фаервол |
| Linux/сервер: `браузер не открылся` при запуске панели | так и должно быть без графики: копируйте адрес из окна запуска. Вход в VK — токеном `LOGIN:PASS:TOKEN`, переносом `data/session_*.json` или `xvfb-run -a python3 src/vk_auth.py --login` |
| Linux: Chromium не стартует (`Failed to launch`, root, контейнер) | проект сам добавляет `--no-sandbox` и `--disable-dev-shm-usage`; если браузера нет вовсе — `sudo python3 -m playwright install --with-deps chromium` (или `sudo apt install chromium`) |
| Linux: панель пишет «файловый менеджер недоступен — путь: …» | на сервере нет `xdg-open`: папку открывает не панель, а вы — по показанному пути |
| Linux: `Permission denied` на `data/` или `.venv/` | проект должен лежать там, где у пользователя есть запись: `sudo chown -R $USER:$USER data .venv` |
| Windows: в логе `браузер msedge не установлен — пробую следующий` | так и надо: Edge в системе нет, вход идёт следующим браузером из списка (Chrome, встроенный Chromium, PATH). Сама ошибка Playwright про `is not found at …\msedge.exe` — не сбой, а перебор браузеров: они теперь идут в порядке «сначала тот, что установлен» |
| В логе `сбой на окне … OperationalError: database is locked` | база на миг занята другим соединением (панель, живой Excel-экспорт). Запись теперь повторяется сама, окно не теряется; если такая строка повторяется постоянно — закройте второй экземпляр парсера или панель, работающую на той же папке `data/` |
| В карточке «Аккаунты» число больше, чем строк в `data/accounts.txt` | исправлено: карточка считает строки файла (база — только статусы), а накопившиеся двойники `+7904…`/`7904…` сливаются автоматически при первом запуске (в логе `база обновлена: строки аккаунтов слиты по телефону`) |
| В логе окно вида `15.10 03:42:34–15.10 03:42:48` (десяток секунд) | исправлено: «за 6 часов» почти всегда длиннее ровно 6 часов на десяток секунд, и такой хвост больше не выделяется в отдельное окно с лишним запросом к VK. Границы окон в логе теперь пишутся с секундами — видно, что окна не «нулевые» |
| Нужно посмотреть лог прошлого прогона, а панель уже перезапускали | панель дублирует весь лог в `data/logs/panel-YYYYmmdd.log` (файлы режутся по 8 МБ: `-2`, `-3`…). Там же видно, на чём кончился запуск: `ВК молча отдаёт пустую выдачу`, `молча пустое — оставляю следующему «Старту»`, `раунд прерван, недобитых окон N`, `итого за … мин`. **В файле бывают логины и прокси — никому не передавайте его целиком**, вырезайте нужные строки |
